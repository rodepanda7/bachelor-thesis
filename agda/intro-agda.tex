\section{Intro to Agda}
% https://serokell.io/blog/agda-in-nutshell

This section, aims to provide a brief introduction to Agda, a dependently typed functional programming language and proof assistant. 
Agda uses strong typing and dependent types, and thus it can be used to write proofs constructively, which can be run as programs \cite{Norell2007}.
In order to understand the formalisation of \lab in Agda, we discuss the following basic concepts: 
data types, parameterised data types, functions, dependent data types, implicit arguments, and hole-based programming \cite{AgdaDocs}.

\subsection{Data Types and Functions}
Data types, can be seen as a collection of values that have something in common.
This collection is usually structured in some kind of way, such as a list or a tree \cite{Norell2007}.
Elements of a data type can be constructed using constructors, which are functions that return a value of the data type.
In Agda, we can create a data type with the \textsf{data} keyword, followed by the name of the data type and its constructors \cite{AgdaDocs}.

\Cref{ex:agda-data-type} shows an example of a simple inductive data type: the natural numbers. It defines two constructors:
\begin{itemize}
  \item \textsf{zero}, representing the base case (the number zero),
  \item \textsf{suc}, which takes a natural number and returns its successor.
\end{itemize}

The keyword \textsf{Set} in the type signature indicates the type of type. This is analogous to \textsf{*} in Haskell, which denotes the kind of types.

  \input{agda-code/data-type-ex.tex}
\end{example}
Data types in Agda can also have parameters. 
This makes them more flexible and allows for the creation of more complex data types.
\Cref{ex:agda-parametrized-data-type} shows such a data type, which is a list that can hold elements of any type \(A\).
We can make a list of natural numbers, which will have the type \textsf{List ℕ}, or a list of Booleans, which will have the type \textsf{List Bool}.
Note that the parameter $A$ occurs before the colon, indicating that it is a type parameter.

\begin{example}
  \label{ex:agda-parametrized-data-type}
  \textbf{List as a parameterised data type in Agda:}:
  \input{agda-code/data-type-par-ex.tex}
\end{example}
Functions in Agda are defined using pattern matching, similar to Haskell. 
Each function has a type signature that defines the type of the function and its arguments.
After the type signature, a number of equations follows, defining the function for each pattern,
where functions can be recursive. \Cref{ex:agda-function} shows such a function, which doubles a natural number.

Functions can also be higher order, taking other functions as arguments or returning functions as results.
Function application of function $F$ to argument $x$ is written as $F \ x$ in Agda.
Infix functions are denoted with underscores, such as $\_::\_$ in \cref{ex:agda-parametrized-data-type}, where it is the constructor for the list data type.
The first argument can be put on the left side of the constructor and the second argument on the right side, such as in $x :: xs$.

\begin{example}
  \label{ex:agda-function}
  \textbf{Function that doubles a natural number in Agda:}
  \input{agda-code/function-double-ex.tex}
\end{example}
\Cref{ex:agda-dependent-data-type} presents a dependent data type, which is a vector that has a length that is encoded in its type.
In this example, we see that the type of a vector depends on a natural number, which is different for both constructors.
The dependent type occurs after the colon, which is $\mathbb{N}$ in this case. 
Dependent types differ from parameterised types in that they can vary between constructors, whereas parameterised types use a single type parameter shared by all constructors.

The constructor $\_::\_$ in \cref{ex:agda-dependent-data-type} is also an example of a dependent function.
That is, the return type of $\_::\_$ depends on the value of the implicit argument $n$. The argument $n$ is implicit, denoted by the curly braces around it.

We see that $[]$ constructs a vector of length zero, resulting in type $\mbox{\textsf{Vector} } A \mbox{ \textsf{zero}}$, 
while the constructor $\_::\_$ constructs a vector of length $n+1$, resulting in type $\mbox{\textsf{Vector }} A \mbox{ \textsf{(suc} } n)$.
Note that the implicit argument $n$ can be inferred from the input type $\mbox{\textsf{Vector} } A \ n$.

\subsection{Hole-Based Programming}
Agda is designed to be used with the Emacs text editor, and the combination provides a way to construct definitions and proofs interactively \cite{agda-emacs-mode, AgdaDocs, Norell2007}, which is called hole-based programming.
While basic support for hole-based programming is available in other text editors, not all features are supported.
Visual Studio Code, for example, has some basic support, while support for Vim is more limited and experimental \cite{AgdaDocs}.

In hole-based programming, terms can be constructed step by step, using question marks as placeholders. These turn into holes, indicating incomplete definitions.
It is best to show this with an example. Note that we could use more holes in \cref{ex:agda-hole-based-programming},
but we feel like this example is sufficient for understanding the concept of hole-based programming.

\begin{example}
  \label{ex:agda-hole-based-programming}
  \textbf{Hole-based programming in Agda:} \\
  This example defines the function \textsf{plus} that adds two natural numbers.
  It defines the function with a question mark, which we can fill in later. The type signature is already given.
  \input{agda-code/hbp-plus-1.tex}
  Pressing the keys \emacs{C-c C-l} (while pressing the control key, typing c and then typing l) loads the file and transforms the question mark into a hole.
  \input{agda-code/hbp-plus-2.tex}
  We can now let Agda give the arguments of the plus function by pressing \emacs{C-c C-c}. The following prompt is shown:
  \begin{verbatim}
    pattern variables to case (empty for split on result):
  \end{verbatim}
  Since we do not have any arguments yet, we can press enter.
  \input{agda-code/hbp-plus-3.tex}
  Now, we would like to do a case distinction on the first argument. We let Agda do this by pressing \emacs{C-c C-c} again.
  The same prompt will be shown as before, but now we type the first argument $x$.
  \input{agda-code/hbp-plus-4.tex}
  Inside the first hole, we press \emacs{C-c C-,}. This gives us information about the type of the hole and all the variables in scope,
  which are the variables that we can use to fill in the hole. We get something like the following output:
  \begin{lstlisting}
    Goal: $\mathbb{N}$
    _________________________
    $x_1$ : $\mathbb{N}$
  \end{lstlisting}
  This tells us we need to produce a natural number and that we can use the variable $x_1$ inside this hole.
  Since we have that $0 + x_1 = x_1$, we fill in the hole with $x_1$, which can be done by typing $x_1$ inside the hole and pressing \emacs{C-c C-space}.
  We can type the subscript $1$ in Emacs by typing \textsf{$\backslash \ 1$}. Agda allows this usage for unicode characters, since Agda files are UTF-8 encoded \cite{AgdaDocs}.
  The hole will be filled in and Agda will check if the type of the hole is correct. Pressing \emacs{C-c C-f} will move the cursor forward to the next hole.
  \input{agda-code/hbp-plus-5.tex}
  Typing \emacs{C-c C-,} in this second hole gives us the type of the next hole. The output will be similar to the following:
  \begin{lstlisting}
    Goal: $\mathbb{N}$
    _________________________
    $x_1$ : $\mathbb{N}$
    $x$ : $\mathbb{N}$
  \end{lstlisting}
  The goal is to produce a natural number, which is the result of an addition. Since one of the arguments is $\textsf{suc } x$, we know the result is not zero, 
  and thus we use the \textsf{suc} constructor.
  We fill in the hole with \textsf{suc ?} and type \emacs{C-c C-space}.
  We closed a hole and made a new hole, which is the argument of the \textsf{suc} constructor. We now have the following code:
  \input{agda-code/hbp-plus-6.tex}
  We can fill in the last hole with $\textsf{plus } x \ x_1$ and press \emacs{C-c C-space} to close the hole.
  The final code looks like this:
  \input{agda-code/hbp-plus-7.tex}
\end{example}

\Cref{ex:agda-hole-based-programming} shows how to use the commands \emacs{C-c C-l}, \emacs{C-c C-c}, \emacs{C-c C-f}, \emacs{C-c C-space}, and \emacs{C-c C-,} to interactively develop a function in Agda.
However, there are many more commands available in Agda to help with hole-based programming.
For a complete list of commands, we refer to the Agda documentation about Emacs Mode \cite{agda-emacs-mode}.
